# Real F1 Cars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every team races its own real 2023 F1 car (free Sketchfab models, real liveries) with real tyres and a helmeted driver, at the same frame rate and load time as today.

**Architecture:** A headless Blender pipeline (`scripts/cars/*.py`) downloads each model with the user's stored Sketchfab key, normalises it to the game's car frame, strips its wheels, adds markers, builds two LODs with the original's detail baked into normal maps and exports one GLB per team plus a shared tyre and helmet GLB into `public/models/`. A node test inspects every GLB. The browser loads them through a small loader (`public/js/carModels.js`) and `game3d.js` uses them in place of the procedural body, which stays as the fallback.

**Tech Stack:** Blender 5.2.2 (`/Applications/Blender.app/Contents/MacOS/Blender -b --python`), three.js r186 `GLTFLoader` (`three/addons/loaders/GLTFLoader.js`), WebP textures in GLB, Node `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-19-real-f1-cars-design.md`

## Global Constraints

- Free models only; the eleven picks are the spec's table (ten teams; `redbull-suzuka` uses the RB19). Never a Sketchfab upload named `unpacked-*` (EA rips).
- The Sketchfab key is read inside Blender from the "MCP for Blender" add-on preferences (`bpy.context.preferences.addons['addon'].preferences.sketchfab_api_key`); never printed, logged, written to a file or the repo, or sent anywhere but `api.sketchfab.com`.
- Car frame: x forward, y left, z up, metres, origin between the axles on the ground (`carShape.js`); three.js (x, z, −y).
- Physics untouched: `WHEELS`, `WHEELBASE_M` 3.6, `TRACK_WIDTH_M` 1.6, `WHEEL_RADIUS` 0.36 keep their values.
- Gates: Monza, High, 21 bots, `node scripts/browser-check.mjs --track monza --level high --bots 21 --eval <prof.js>` frame p95 ≤ 8.3 ms; session start to first drawn world ≤ today's (~1.05 s headless, measured as in commit a67785b).
- Credits: every model's name, author, licence and URL shown in the game.
- Downloads and Blender intermediates live under `scripts/build/cars/` (gitignored); only the final GLBs and `public/models/credits.json` are committed.

## Review Focus

1. A team's GLB missing or failing to load mid-session: that team's cars draw the procedural car, nothing throws, no retry every frame (Task 4 test `carModels: a failed load falls back once`).
2. A car joining before its GLB has loaded: procedural first, swapped for the real car once loaded, without a visible hitch on other cars (Task 4 browser check: join with an empty cache).
3. Ghost cars (`ghost` opacity) with multi-material GLBs: every material of a ghost car fades, other cars of the same team don't (Task 4 test on `cloneForCar`).
4. Low quality: only the far LOD is used and the frame rate on Low doesn't drop (Task 4 test `detailFor('low') === 'far'`; Task 7 fps at Low).
5. Onboard views of a car whose marker is missing: the cameras fall back to `EYE`/`WHEEL_POS` (Task 4 test on `eyeFor`).

### Task 4: The game draws the real cars

**Files:**
- Create: `public/js/carModels.js`
- Modify: `public/js/game3d.js` (`makeCar`, `updateWheelBatch`, onboard camera and steering wheel at lines ~1663–1700, ~1824–1860, ~1895–1930), `public/js/views.js`
- Test: `test/carModels.client.test.js`, `test/views.client.test.js`

**Interfaces:**
- Consumes: Task 2/3 GLB node and material names.
- Produces (`carModels.js`):
  - `loadTeamCar(teamId, load = gltfLoad) -> Promise<CarAsset | null>` — cached per team (one request ever; a failure caches `null`); `redbull-suzuka` loads its own GLB.
  - `CarAsset = { near: THREE.Object3D, far: THREE.Object3D, wheels: { [name]: { pos: [x, y, z], radius, width } }, eye: [x, y, z], wheelPos: [x, y, z], head: [x, y, z] }` (car frame metres).

  - `detailFor(level) -> 'near' | 'far'` — `'far'` on Low.
  - `preloadTeams(teamIds) -> Promise<void>`.
  - `loadParts() -> Promise<{ tyres: { S, M, H, rim }, helmet, shoulders } | null>`.
- Produces (`views.js`): `eyeFor(view, asset) -> [x, y, z]` — cockpit = `asset.eye`, T-cam = `asset.eye` + (−0.16, 0, +0.28); `EYE[view]` when `asset` or its marker is missing. `wheelPosFor(asset) -> [x, y, z]` — `asset.wheelPos` or `WHEEL_POS`.
